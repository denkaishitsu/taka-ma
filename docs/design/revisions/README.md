## 記録の型

障害・事故を契機とする改訂は、[2026-09-04 の記録](2026-09-04_mbp-unreachable-outage.md)を型として個別記録を書く。最低限、次を持たせる。

1. **Context** — 何が起きたか（1 段落）
2. **実測（判定根拠）** — 事実とその根拠ログを対にした表。推測は書かない
3. **判断一覧** — 何をどう変えたか、なぜそれを選んだか
4. **設計反映マップ** — どの設計書のどの節を改訂したか（リンク）
5. **完了条件** — 何を機械で測れば是正されたと言えるか
6. **未検証事項** — 断定できなかったことを正直に残す

ファイル名は `YYYY-MM-DD_<英小文字スラッグ>.md`。
